# Rust 的借用类型 &CStr 和 unsafe

## 借用类型 &

& 是 Rust 的引用（借用）

```rust
let a: i32 = 10;
let b: &i32 = &a;
```

这里的 `&i32` 就是借用一个 `i32` 类型的值

同样也可以换成其他类型：

```rust
let name: String = String::from("Hello");
let borrowed: &String = &name;
```

~但是这里的 `&` 和 Kotlin 的 `?` 不是同一种东西~ ~ai又写废话~

_我在和ai对话的时候也没说错/说这个，不知道写上去干嘛，argon说是能说人话，但是怎么能这么蠢_

Kotlin 的 `Int?` 对应的其实更加接近 Rust 的 `Option<i32>`

```rust
let x: Option<&str> = Some("Hello");
```

~甚至还能组合起来，表示一个可能不存在的字符串借用是~

这意味着你可以将 Rust 的两个特性——`Option` 和 `&`（借用）——组合成一个类型：`Option<&str>`

-   `&str` 是一个借用的字符串切片：即对由其他所有者所拥有的字符串数据的“视图”。
-   `Option<...>` 则表示该值可能不存在

因此，`Option<&str>` 的含义是：“可能是一个借用的字符串，也可能什么都没有”。你示例中的 `Some("Hello")` 正是如此：一个包裹着 `&str` 的 `Some`

在 Rust 中，这些概念是相互独立的，因此你可以自由地将它们组合使用

而在 Kotlin 中，仅仅是可空性

在rust当中甚至能option套option，但是Kotlin会把int??合并为int?

## `&CStr` 又是什么？

因为 C 语言的字符串是通过 `\0` 结尾的，但是 Rust 的 `&str` 是通过长度判断的。

所以 Rust 提供了 `CStr` 这种类型来处理 C 字符串。

```rust
use std::ffi::{CStr, CString};

let owned = CString::new("Hello").unwrap();
let borrowed: &CStr = owned.as_c_str();
```

这里：

-   `CString` 拥有字符串内存
-   `&CStr` 只是借用，不负责释放内存

大概就类似于 `String` 和 `&str` 的区别

## `unsafe` 不是类型

其实不是

~一开始我还以为 `unsafe {}` 也是一种类似 `Some()` 的模具，需要匹配才能使用~

但是它实际上是 Rust 的一个语法块

比如：

```rust
let name = unsafe {
    CStr::from_ptr(ptr)
};
```

因为 `CStr::from_ptr()` 是 `unsafe fn`，所以调用的时候必须处于 `unsafe` 上下文当中

这里的 `unsafe` 不是进行类型匹配，而是告诉编译器，我自己负责保证这里的指针是有效的，并且满足函数的安全条件

不过它也不会自动检查指针有没有问题

其实 `unsafe` 更像是一种**显式标记安全责任的语法**、（而不是上文所提到的rust的某种枚举类型匹配/或者说泛型枚举匹配，类似于some{}，？我不太确定它的具体中文名是什么

所以

-   `Option<T>` 是泛型枚举，类似 Kotlin 的 `T?`
-   `&T` 是借用类型，可以用于其他类型
-   `&CStr` 是借用 C 风格字符串
-   `unsafe {}` 不是类型，而是允许执行不安全操作的语法块

# 关于生命周期

~我之前认为就是就比如一个加a和b的函数，加了‘ 就能保证生命周期覆盖a和b？~

但是实际上

目的和我理解相同，但是实现方式算是

`'a` 不会保证或延长 a 和 b 的生命周期，而是要求返回的引用不能超过它们共同有效的范围

比如一个比较两个数并返回较大值引用的函数

```rust
fn max<'a>(a: &'a i32, b: &'a i32) -> &'a i32 {
    if a > b { a } else { b }
}
```

这里：

-   `<'a>` 声明一个生命周期参数

顺便提一句这里不是泛型，**Rust 的 <> 不只是声明泛型类型，也可以声明生命周期参数**

-   `a: &'a i32` 表示 a 是带有生命周期 `'a` 的引用
-   `b: &'a i32` 同理
-   `-> &'a i32` 表示返回的引用也受到 `'a` 的限制

（或者说，  
可以简单理表示返回引用的生命周期也与 ‘a 关联

期不能超过 a 和 b 中较短的那个

比如 a 能活 10 秒，b 能活 5 秒，那么返回的引用最多只能在它们共同有效的那 5 秒内使用（这里只是方便理解的比喻）

如果只是计算 `a + b` 并返回 `i32`，因为返回的是数值而不是引用，就不需要写 `'a`
