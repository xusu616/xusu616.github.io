# 在想要时序逻辑的时候被优化为“组合”逻辑，或者说同时赋值

\>具体就是比如说一段移位逻辑

```Verilog
always @(posedge clk) begin
    q1 = in;
    q2 = q1;
    out = q2;
end
```

这里实际上并不能实现我们想要的移位，逻辑，因为实际上这段代码会被优化为

in --> q1 q2 out

相当于执行了一段完全相同的赋值，图片应该长这样

![=阻塞赋值](/img/IMG_20261014_204911.jpg)

注意，实际上，Verilog并不会像其他现代语言甚至汇编语言一样逐句执行，它是完全同步的（即阻塞）他们会直接尝试并列执行

# 使用非阻塞赋值

想要写出移位的话就要使用非阻塞赋值

同样的

```Verilog
always @(posedge clk) begin
    q1 <= in;
    q2 <= q1;
    out <= q2;
end
```

长这样，可以根据时钟移位

## 等等，既然是阻塞，那为什么反而能同时同步

因为这里实际上不是硬件上的那个阻塞的意思，意思是软件上的阻塞的意思，实际上，两个阻塞概念经常被混用

好吧我说人话就是在一个always块当中，上一行没有执行完，下一行就卡住，但是Verilog仍然是同步运行的，只是被阻塞了（或者说是能同步运行的

**它会强迫等待时钟运行完了之后，变为新值再执行，所以看起来反而同步了**

\>另外一句，这里不是always @(\*)所以实际上，是受时钟边沿控制的时序逻辑，而非组合逻辑
